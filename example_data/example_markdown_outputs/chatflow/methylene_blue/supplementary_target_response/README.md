# Supplementary Target-Responsiveness and Workflow-Control Evaluation

This directory archives supplementary model-evaluation outputs for methylene-blue sustained-release formulation redesign. The evaluation examines whether formulation recommendations respond to changes in the requested 0-4 h release-related target, remain consistent across repeated runs, and depend on the workflow condition.

## Experimental Conditions and Run Counts

- `original_dis_chatflow_105/`: three Qwen3.6-plus runs using the original DIS Chatflow and the original 105% target. These runs form the workflow-control condition.
- `tomo_mygo_adapted_110/`: three Qwen3.6-plus runs using the TOMO/MYGO-adapted Chatflow and a 110% target.
- `tomo_mygo_adapted_90/`: three Qwen3.6-plus runs using the TOMO/MYGO-adapted Chatflow and a 90% target.
- `../../../skills/methylene_blue/supplementary_target_response/`: one skill-assisted GPT document for each final target, 90% and 110%.

Run counts are based on the files present in the approved source directory. No missing repeats were imputed.

## File Organization

Each Chatflow replicate directory contains:

- `mechanism_answer.md`: the source mechanism response, copied byte-for-byte.
- `optimization_answer.public.md`: the optimization response; transient Dify download URLs were removed where present.
- `transcript.public.json`: the complete transcript with prompts and model answers preserved; private local paths and transient Dify download URLs were removed.
- `optimization_report.public.docx`: present when generated by the source run; the external local template relationship and creator metadata were removed without changing visible report text.

`source_checksums.csv` records the source filename, source SHA-256 checksum, public repository file, public-copy transformation, and public-copy checksum. The approved source files remain unchanged outside this repository.

## Machine-Readable Results

- `processed_data/methylene_blue_target_response_recommendations.csv`: run-level formulation recommendations and mechanistic rationale.
- `processed_data/methylene_blue_target_response_run_metadata.csv`: model, workflow, timing, repeat count, generation-setting availability, and source checksums.
- `processed_data/methylene_blue_workflow_control_comparison.csv`: fixed-base-model comparison of the original and TOMO/MYGO-adapted Chatflow conditions.

The prompt/task instructions are retained within each public transcript. Reusable workflow prompt modules remain under `prompts/DIS/` and `prompts/MYGO/`.

## Interpretation Boundaries

These supplementary runs evaluate recommendation-process target responsiveness, repeat-run stability, and workflow dependence. They do not demonstrate that a 90% or 110% target was achieved experimentally.

The original-versus-adapted Chatflow comparison is a workflow-control analysis. It is not a strict ablation of an individual skill, node, TOMO component, or MYGO component, and it should not be presented as a deterministic ranking of base-model capability.

The three original-Chatflow runs provided mechanistic or validation discussion but no explicit numeric next-step formulation. The six adapted-Chatflow runs provided numeric candidates. However, the 90% Chatflow prompt used the internally ambiguous phrase "increased to 90%"; all three adapted runs interpreted that wording as acceleration and recommended lower K4M/higher K100LV. This direction is therefore recorded as an output consistency finding, not as successful response to a literal 90%-of-baseline target.

The two GPT source filenames do not agree with their final optimization sections: the file named 90% ends with a 110% recommendation, while the file named 110% ends with a 90% recommendation and retains an earlier 110% background statement. Repository filenames follow the final recommendation section, and the mismatch is retained in the checksum and metadata notes.

Exact provider-side model identifiers, model-provider metadata, workflow version, prompt version, and temperature/generation settings were not recorded in the output files. Qwen3.6-plus and the workflow conditions are taken from the experiment description. The GPT documents do not identify their exact model in their contents; the experiment description says GPT-5.4 Thinking, whereas the source filenames say GPT 5.5, so the machine-readable records mark the exact GPT version as unresolved.

HPMC amounts are recorded exactly as reported. Their unit was not reliably or consistently recorded and was not inferred. `k4m_fraction` is the derived dimensionless value `K4M / (K4M + K100LV)` calculated only when both recommended amounts were explicit.
