# Comparison Verdict Generator

## Scope

Execute branch-4 comparison and final same/different verdict only. Keep full mechanistic authoring in branch 5.

Router mapping (fixed):
- Branch `4`: Two-drug comparison -> this skill
- Branch `5`: Mechanism analysis -> `mechanism-summary-generator`

## Inputs

- `query_text` (string, required; used to identify target group pair like `Group A vs Group B`)
- `image_analyses` (object or array, required, must match `../_contracts/image_analysis.schema.json`)
- `experiment_config` (object or JSON string, required)
- `mechanism_summary` (object, optional; supports v1/v2 from `../_contracts/mechanism_summary.schema.json`)

## Output Contract

- `comparison_table_with_verdict` must validate against `../_contracts/comparison_table_with_verdict.schema.json`
- Target emission is v2 branch (`same`/`different` verdict).
- Legacy v1 branch remains for backward compatibility.
- `verdict` must be `same` or `different`.
- `verdict_line` must be exactly `Verdict: same` or `Verdict: different`.
- `confidence` must remain in `[0,1]`.
- `additionalProperties` must remain `false`

## Execution Rules

1. Resolve comparison groups:
- Parse explicit pair from `query_text` (for example `Group A vs Group B`).
- Match using `group_id` in `image_analyses` (case-insensitive).
- If unresolved or not exactly two comparable groups, fail with `GROUP_MAPPING_FAILED`.
2. Build fixed eight dimensions in this order:
- `color_change`
- `shape_change`
- `surface_texture_change`
- `volume_change`
- `dissolution_speed_time`
- `physical_state_change`
- `dissolution_medium`
- `fragment_distribution_density`
3. Sort each group by `time_h` (null times last). Build aligned comparison windows.
4. Produce 8-row comparison evidence table:
- Columns: `Dimension | Group A | Group B | Key Differences`.
- Each row must summarize both groups and highlight key difference on that dimension.
5. Extract key time-axis differences:
- Identify transition timing differences (for example coating rupture, fragment surge, residue disappearance).
6. Apply mandatory verdict rule (do not count dimension differences):
- Prefer verdict basis on:
  1) mechanism pattern consistency
  2) time-course shape alignment
- Same if ALL are true:
  A) mechanism pattern consistent
  B) key transitions in same order and timing broadly aligned
  C) differences are intensity-level only
- Different if ANY are true:
  A) mechanism pattern differs qualitatively
  B) time-course shape differs clearly
  C) difference changes practical class label
7. Timing tolerance rule for `same`:
- Treat timing as aligned when difference is within about 1-2 sampling intervals OR within about 25-30 percent of total duration.
- Use the more tolerant threshold when sampling is coarse.
8. Uncertainty preference:
- If uncertain and no explicit mechanism/shape difference evidence exists, prefer `same`.
9. Release-impact note:
- Add brief qualitative impact statement on release/exposure trend.
- Do not over-speculate on PK.
10. Build final v2 output fields:
- `dimension_table`
- `time_axis_key_differences`
- `overall_summary`
- `release_exposure_note`
- `decision_basis`
- `verdict`
- `verdict_line`
- `confidence`
11. Confidence scoring:
- Base `0.50`
- Add `0.15` if both groups have sufficient timepoint coverage
- Add `0.15` if mechanism pattern evidence is explicit
- Add `0.10` if transition timing evidence is explicit
- Subtract `0.20` if major missing windows exist
- Clamp to `[0,1]`.
12. Validate schema before return.

## Failure Payload (branch-scoped)

```json
{
  "branch": "4",
  "error_code": "GROUP_MAPPING_FAILED | TIME_ALIGNMENT_FAILED | OUTPUT_NOT_JSON | SCHEMA_VALIDATION_FAILED",
  "message": "string",
  "failed_fields": ["string"]
}
```
